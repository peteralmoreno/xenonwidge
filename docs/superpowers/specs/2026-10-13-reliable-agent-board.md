# Reliable agent-operated Board

The sidebar is the everyday control panel; Ranch is the activity display. This iteration adds three connected capabilities: visible companion recovery, preferential continuity across related tasks, and documented local agent access to the same Board.

## Requirements

1. Connection & recovery remains accessible when the companion is down. Show connected/starting/offline/unresponsive/port-conflict/version-mismatch/busy-upgrade states with a concrete explanation, expected address, observed version/process identity when authenticated, home, last successful contact and sanitized recent logs. Normal operation has no red connection dot. Offline or reconnecting states have text, not color alone.
2. Reconnect reuses a healthy companion or starts a missing one. Restart when idle uses the existing authenticated shutdown refusal for active/unresolved work. A busy request remains pending and visibly cancelable; it must not stop current work or repeatedly hammer shutdown. Quit-and-stop-when-idle is explicit and cancelable. An unrelated listener is never killed. No silent port changes or fallback to a different bot home.
3. A companion ownership lock is acquired before constructing the manager or writing home data. Concurrent startup must not create two writers. A stale lock is reclaimed only after verifying its recorded owner is gone; ambiguous ownership is a visible recovery state. Never use a PID alone to authorize killing a process. Logs and diagnostics exclude credentials, instructions, task results and full process command lines.
4. Sticky family preference uses normalized family name plus canonical project path; color is presentation, not identity. Family default is off. Each task can inherit/on/off. Explicit assignments and manually ordered bot queues win. Among eligible shared tasks prefer continuing the same sticky family, without overriding release, dependencies, model checks, workspace ownership or read-only policy. Existing per-task/per-session context rules are unchanged.
5. A preferred bot gets a short handoff opportunity, not indefinite ownership. Use a documented 30-second preference window; banked/closed/failed/ineligible owners release preference immediately. After three consecutive sticky picks, let older eligible unrelated shared work go first. Record affinity only after a successful dispatch, never for a failed launch. Follow-ups inherit the parent's family and stickiness. Explicit assignment remains the existing way to require a particular bot; do not add a second hard-assignment system.
6. Sidebar task details show the reason work cannot move and a Sticky control. Family controls expose the shared default and a reset/clear preference action. Bot cards show current work and the next three pending tasks, with sticky markers and understandable preferred-bot text. Full Board editors preserve new fields when editing older tasks.
7. AI Sync opens from the sidebar in a dedicated pop-out. Show bot home, actual local command invocation, interaction catalog, copyable agent instructions, access mode, previewed change sets and recent changes. Agent-authored text is data and must never execute as markup or commands in the app.
8. Ship a local CLI and versioned JSON interaction catalog. CLI credentials are read internally from private companion configuration; instructions/catalog never contain secrets. Provide inspect, preview and apply flows with JSON output and actionable nonzero exits. API and CLI operate through the companion; never edit task JSON files directly. Keep one user-facing connection key.
9. AI access modes are inspect, organize and operate. Enforce the selected mode server-side on the AI routes. Inspect reads/previews only; organize creates held drafts and edits pending ticket metadata, dependencies/families, assignment and queue order; operate additionally permits explicit release/start/work-check operations. No delete, arbitrary filesystem, shell, secret-reading, permission-change or companion-restart operation in the agent catalog. This is an application permission boundary, not a sandbox against a local process with access to the user's private files.
10. A Board sweep previews exact before/after changes with actor label and revision preconditions. Apply must either validate and persist the entire editing batch or leave it unapplied. Never auto-release work as a side effect of organizing. Stale revisions reject the entire batch; a reused change-set ID returns the previous receipt without applying twice. Successful changes appear through normal Board polling and a durable audit entry. Preview/apply do not run an LLM themselves.
11. Default AI access is inspect. Provide a copyable sweep prompt: clarify titles, flag missing acceptance criteria, suggest families/dependencies, preserve meaning, and keep drafts held. Mode choices live in the pop-out; no additional key-copying flow.
12. Existing saved data loads without losing profiles, tasks, sessions, colors, releases or context settings. Use the next release 0.17.0. Package only explicit source/runtime files, including new CLI/catalog/guides, and exclude local data. Do not install, restart, prompt models, or modify the user's live tasks during development.

## Current implementation to preserve

Version 0.16.0 has short/long native sidebar, Board detail/editor, Bot Bank/Factory, individual/town bells, native Full Board/Settings pop-outs and A/B Ranch display. `ensureCompanion` already authenticates/reuses a compatible process and refuses busy upgrades. Main-process startup currently flattens errors and ignores detached process output. Pickup logic is duplicated between `pollWork` and `autoPickup`; both must use one new policy. `ranch.json` is authoritative; portable home task files are exports, not the agent mutation interface.

## Delivery

Tests use temporary homes, mocked native terminals and ephemeral listeners. Include an actual hidden packaged Electron smoke. Report evidence and remaining limitations honestly. Preserve all pre-existing uncommitted work. Implement in the existing checkout on a new feature branch; do not stash/reset/commit unrelated changes or publish anything.
